## 1. 方法与证据链

三类证据，全部可复现（脚本见 §9）：

| 证据 | API | 拿到什么 |
|---|---|---|
| 仓库元数据 | `HfApi().dataset_info(repo_id, files_metadata=True)`；`GET /api/datasets/{id}?blobs=true` | 逐文件真实字节、`usedStorage`、license tag、language tag、gated、lastModified |
| 行数/未压缩体积 | `datasets-server /size`、`/splits` | 每 config/split 的 `num_rows`、`num_bytes_parquet_files`、`num_bytes_memory` |
| 真实文本样本 | `datasets-server /first-rows`（100 行）；无索引时用 **HTTP Range ≤256KB** 读 gzip 头 / **parquet footer + 单 row group** | 字段名、样本文本、CJK 占比 |

**token 数怎么来的**：把样本原文喂进项目自己的 `data_cache/chat_pack_v13/bpe_tokenizer.json` 实测 `token/字符`，再乘 API 给的行数（rows 法）与未压缩字节（mem 法）交叉校验；两法差 <1.6 倍才标 `high`。
标注约定：`high` = 两法一致；`low` = 仅单法可用；`coarse` = 只能按压缩比反推（±50%）。

> ⚠️ API 的一个坑：`dataset_info()` 在 huggingface_hub 2.2.0 下 `cardData` 返回的是 YAML 对象而非 dict，直接 `.get("license")` 会静默拿到 `None`。本文 license 一律取 `tags` 里的 `license:*`，与 `cardData` 交叉核对过。

## 2. 全局约束：先算清楚 20k BPE 的账

这是本次调研最重要的发现，直接影响选型。

**实测 `bytes/token`（样本原文 → 你们的 tokenizer）**：

| 语料类型 | token/字符 | bytes/token |
|---|---|---|
| 中文网页（ChineseWebText2.0-HQ） | 0.727 | **3.51** |
| 中文教材/教育（IndustryCorpus2） | 0.684 | 3.58 |
| 中文编程散文（IndustryCorpus zh/program） | 0.587 | 3.92 |
| 代码（gitee / UltraData-Code） | 0.565 | **1.77** |
| 英文数学（NuminaMath-1.5） | 0.489 | **2.04** |

结论：**这个 20k 词表对英文/代码的效率只有中文的 ~55%**（正常英文 tokenizer 约 4 char/token，这里只有 2 char/token）。
→ 同样一个 token，中文语料覆盖 3.5 字节信息，英文代码只覆盖 1.8 字节。**英文语料在「磁盘」上便宜，但在「训练时间」上贵一倍**。你们真正的瓶颈是时间（206M token/h），所以中文母语语料优先。

**磁盘/时间换算（按 24 GB 可用、206M token/h）**：

- 训练 1B token = **4.85 h**
- tokenize 成 uint16 `.bin` = **2 B/token**（2.15B token → 4.3 GB）
- 峰值磁盘 = parquet + 已转 bin；**必须逐数据集 tokenize 完就删源**，否则 12.55 + 12.06 = 24.6 GB 会刚好爆盘

**采样实测（关键证据）**

- `gitee-code` 4 个 offset 的 `/first-rows` 返回**完全相同**的 58 行（Java 30 / C++ 22 / CMake 6），CJK 占比 **0.0006**。它确实是 Gitee 快照，但正文是纯 ASCII 代码，**中文注释几乎为零**。「用 Gitee = 中文代码语料」这个直觉不成立。license 为 `other`（Gitee 仓库版权），商用有风险。
- `Ling-Coder-SFT` 的 `languages` 字段是**编程语言**（`['Python']` 等），不是自然语言；抽样 47 行里 10 行 >10% CJK，整体 CJK 3.3%，即代码为主 + 少量中文解释。这正好符合「代码语料天然以 ASCII 为主」的预期。
- `UltraData-Code` 样本是 TopCoder 的 C++ 题解，CJK 0.0006 → 纯英文。

**结论**：HF 上**不存在**「十亿 token 级、纯中文、license 干净」的代码预训练语料。可行组合是
**`Ling-Coder-SFT`（2.15B，代码+解释，apache-2.0）为骨架**，`Chinese-StackOverflow`（150M，中文问答）+ `IndustryCorpus zh/program`（≈0.5B，中文技术散文）补中文语境；`gitee-code` 仅在能接受 `other` license 时，切 1–2 GB（≈2.5–5B token）做纯代码增量。

## 6. 优先级推导

单一标量 `能力缺口权重 × token/GB`（缺口权重：代码 1.0、数学 1.0、知识 0.6——知识已有 2.82B 覆盖）：

| 候选 | 缺口权重 | token/GB | 得分 | 备注 |
|---|---|---|---|---|
| Ling-Coder-SFT | 1.0 | 343M | 343 | 无需切片，license 干净 |
| **TiWu math-zh** | 1.0 | ~600M | **600** | 单位成本最高 |
| MNBVC/math | 1.0 | ~620M | 620 | 但内容偏小学算术 |
| NuminaMath-1.5 | 1.0×0.5（英文） | 1,530M | 765 | 语言不对，打折 |
| Fineweb-V3 | 0.6 | ~640M | 384 | 仅 0.18B，规模补充不了 |
| IndustryCorpus2 edu | 0.6 | ~430M | 258 | 质量平平 |

**为什么最终把代码排第 1**：代码与数学的缺口分数都是 0.000，但**代码在现有语料里是 100% 缺失**（FineWeb-Edu/维基是散文，数学概念至少还会出现），且 `Ling-Coder-SFT` 是一个**自洽的 6.26 GB 包**——不需要切片决策、license 干净、2.15B token 刚好 10 小时。数学虽然单位成本高 1.7 倍，但 16.36 GB 必须切片，且内容偏「技术+数学」混合，质量方差更大。

## 7. 落地方案（磁盘 / 时间都算过）

```
1) inclusionAI/Ling-Coder-SFT        6.26 GB → 2.15B tok → bin 4.30 GB
2) TiWu-Lab/math-zh 取 4 片          6.01 GB → 3.70B tok → bin 7.40 GB
   (00001.1 / 00001.2 / 00002.1 / 00002.2，共 2,649,106 行)
3) opencsg/Fineweb-Edu-Chinese-V3    0.28 GB → 0.18B tok → bin 0.36 GB
---------------------------------------------------------------
合计                                12.55 GB → 6.03B tok → bin 12.06 GB
训练时间 @206M tok/h                 29.3 h
```

- **峰值磁盘**：逐数据集 `下载 → tokenize → 删源`，峰值 = max(6.26+4.30, 6.01+7.40, 0.28+0.36) = **13.4 GB**，剩 10 GB 余量。
  若先把 12.55 GB 全下完再统一 tokenize，峰值 24.6 GB —— **会爆盘**，不要这么做。
- **建议配比**（8.85B 总量）：通用 40%（2.82B 现有 + 少量重复）/ 代码 25%（2.2B）/ 数学 25%（2.2B，把 3.7B 降采样）/ 教材 10%。
- **重分词适配性**：三个源都是纯文本字段（`messages` / `text` / tar 内 jsonl），20k BPE 直接 encode 即可。注意 `math-zh` 的 `tokens` 列是别人 tokenizer 的产物，**必须用 `text` 重分词**；`Ling-Coder-SFT` 是多轮 `messages`，需先按模板拍平成纯文本，别把 `system` 重复计入。

## 8. 已核实 vs 未核实（重要）

**有 API 硬证据（本文所有表格数字均属此类）**
- 尺寸：`usedStorage` + 逐文件 `size` 求和（两者一致，如 gitee-code 574,748,265,537 B）
- 行数：`datasets-server /size` 的 `num_rows`，或 parquet footer 的 `metadata.num_rows`（TiWu 13 片逐个数）
- license：`tags` 中的 `license:*`
- 语言/质量/内容：真实样本 + 用你们 tokenizer 实测的 CJK/token 比

**只是「听说/推断」，未核实**
- `Ling-Coder-SFT` 的 2.15B token 是抽样外推（1.4M 行 × 1,441 token/行），不是全量统计
- `TiWu math-zh` 的 ≈10B token 是按 4 片抽样外推，误差可能 ±30%
- `gitee-code` 的 1.46T token 只有 58 行样本支撑，且 `/first-rows` 的 offset 参数不生效（4 次返回同一批），**代表性未证实**
- `IndustryCorpus2 education` 的 ≈90B token 是「片数 × 每片行数 × 抽样 token/行」推算
- `hugcode-codesft` 1.50 GB 只有 README 的条数，未抽到内容
- `SkyPile-150B` 已标 665.31 GB，但你们文档里记的是「已用 504M token」，与「现有语料只有 FineWeb-Edu + 维基」的说法**不一致**，建议自查
- `MNBVC` 全库 3,775.75 GB、`Fineweb-Edu-Chinese-V2.2` 2,435.04 GB 只核了总量，未逐子集核实

## 9. 复现命令

```python
from huggingface_hub import HfApi
api = HfApi(token=TOKEN)
i = api.dataset_info("inclusionAI/Ling-Coder-SFT", files_metadata=True)
sum(s.size for s in i.siblings)          # 逐文件真实字节
# license 用 raw API 的 tags（cardData 在 hub 2.2.0 下不是 dict）
r = requests.get(f"https://huggingface.co/api/datasets/{rid}", params={"blobs": "true"})
[t for t in r.json()["tags"] if t.startswith("license:")]

# 行数 / 未压缩体积
requests.get("https://datasets-server.huggingface.co/size", params={"dataset": rid})
# 样本
requests.get("https://datasets-server.huggingface.co/first-rows",
             params={"dataset": rid, "config": cfg, "split": "train", "offset": 0, "length": 100})
```

本次使用的临时脚本（可复用）：`%TEMP%\hf_scan\{search,sweep,mine,verify2,probe2,probe4,pq_probe,rows,budget}.py`。
`pq_probe.py` 演示了「只读 parquet footer + 一个 row group」核查无索引数据集的方法；`probe.py` 演示 gzip Range 探针。
