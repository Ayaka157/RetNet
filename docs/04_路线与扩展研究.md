## 2. 已验证走不通的

### 2.1 在 272M 上追「综合能力」

`docs/09` 当时假设短板是**数据缺口**，于是 v10 加了 R1 推理 + 百科 + 结构化数据、跑了 65k 步。
实测结果：

- 能力上只是**略优但不显著**（143 项配对 1,144 对，McNemar p=0.084，总分 +0.026）
- 有得有失：续写显著更好（+0.146）、语言更好（+0.100）；**指令遵循显著更差**（−0.069）
- 代价 10 小时 46 分，产出是一个 **26.5% 的 think 泄漏**
- 结构化（0.06）与数学（全 0）是**尺度限制**，不是数据缺口

### 2.2 v11 的 8K/4K 路线

`docs/11` 的诊断（R1 样本 97% 被 512 窗口截断）是对的，但**实现方式错了**：
`build_chat_mix_v11.py` 把 v10 那些**已经截断的 512 行**摊平后重新切片成 8192 宽的行——
截断在 v10 构建时就固化进 token 了，**重切窗口救不回来**。

两次运行都被人为中断、零产出：fp16 跑 6 步（按 18.7 s/it 外推要 156 小时），
bf16_4k 跑到 2,248/30,000（12.34 s/it，剩余还要 95 小时），第一次存盘在 2,500 步，**差 252 步没赶上**。

正确做法是 `build_chat_mix_v13.py`：只重切 v9 的 token 流，对 R1 **重新编码**并抬高字符上限。

### 2.3 fp16

`logs/precision_test/` 两个种子在第 20、40 步就是 `loss 0.0 / grad_norm NaN`，
bf16 同期正常（3.05/6.82、2.72/7.83）。`tasks/v11_fp16.json` 指向的就是这条死路。

## 3. 架构扩展研究（已调研，未实施）

### 3.1 线性注意力家族

| 路线 | 代表工作 | 核心思想 | 对本项目的价值 |
| --- | --- | --- | --- |
| 门控线性注意力 | Gated Linear Attention（ICML 2024） | 固定 γ → 可学习逐头门控 + 硬件 chunkwise 内核 | **已部分实施**：`use_gla=true` |
| 选择性写入 | Gated DeltaNet / DeltaNet-2（NVIDIA） | delta rule：`S = γS + β(kvᵀ - kᵀS)` | 「记住用户信息/剧情节点」的正解，未做 |
| SSM 统一理论 | Mamba-2 | SSM ↔ 结构化注意力对偶 | 理论坐标系 |
| 混合头小模型 | Hymba（ICLR 2025） | 半 attention 头 + 半线性头，专为 ≤1.5B 设计 | 小模型形态参考 |
| 神经长期记忆 | Titans（Google 2025） | 可学习记忆模块，测试时写记忆 | 长设定外部记忆（远期） |
| 稀疏化（对照） | NSA（DeepSeek, ACL 2025） | 硬件对齐稀疏注意力 | 长上下文对照路线 |

### 3.2 建议组合

- **A（首选）**：GLA 化——**已完成**
- **B**：DeltaNet 式写入门（~40 行改 MSR 状态更新）→ 角色扮演记忆
- **C**：Hymba 式混合头（2–3 头换 sliding-window attention，~100 行 + 重训）
- **E**：尺寸生长——**已做到 272M**（100M → 143M → 272M，见 [`08`](./08_chunkwise_growth_research.md)）

### 3.3 KV cache 相关

RetNet **不需要 KV cache**：推理 state = 每层 12×64×128 bf16 ≈ 196KB，共约 2.4MB，O(1) 恒定。
对比同规模 Transformer：512 上下文 ≈ 19MB，4096 上下文 ≈ 151MB。
真正可做的是 **state 减肥**（GQA 式共享投影 / fp8 量化）。

## 4. CoT 可行性结论

**实测 + 调研结论：**

- **100M 实测**：直接提问「17 加 25」全错；加「请一步一步推理」提示后更乱（伪推理）。
  **推理期 CoT 在本尺度无效。**
- **272M 仍然成立**：填空类得分 0.07–0.20，数学题全 0（`docs/13` §2）。
- **有效下限**：约 0.5–1B（需大模型蒸馏 CoT 数据）；可靠推理 7B 起；原始「涌现」区间 100B+。
- **小模型蒸馏长 CoT 会失败**：强推理者的 CoT 常有 2,000+ 推理 token，小模型容量装不下，
  学到的结果是「要么复读要么崩」（ICML 2025, *Small Models Struggle to Learn from Strong Reasoners*）。

**本项目的正确姿势**：

| 方案 | 描述 | 评价 |
| --- | --- | --- |
| 保留完整 think | 原样学 R1 输出 | ❌ 272M 装不下（R1 中位输出 1,421 token，512 窗口只装下 2.4%） |
| **剥离 think** | 只留 `</think>` 后的最终答案 | ✅ 推荐——R1 的知识（计算倾向）保留，不展示过程 |
| think 降权 | think 段 loss 权重低 | ✅ 备选，需改数据管线 |
| 短 CoT | 保结构（开→推理片段→关→答） | ✅ 可行，512 窗口下唯一能保完整格式的方案 |

> **本轮实测补充**：v10 的 `<think>` 泄漏不是「模型没学会推理」，而是**数据切掉了答案**。
> 见 [`02`](./02_训练管线.md) §3 的两级截断漏斗。

## 5. 后训练内容（按性价比）

| 内容 | 做法 | 成本 | 收益 |
| --- | --- | --- | --- |
| 长多轮 + 记忆 | 8–12 轮样本 + 埋「记住名字/细节」合成样本 | 低 | **RP 最大短板**（基准多轮 0.25–0.38，是唯一既不贴地板也不贴天花板的核心能力） |
| 大模型蒸馏角色对白 | 用 API 按「设定+场景」生成多样角色对话，规则过滤 | 几十元 | 高：现在 RP 数据 80% 是名著对话 + 规则合成，风格单一 |
| DPO / SimPO 偏好对齐 | 同 prompt 采样两组回复，规则打分（口癖/跑题/碎句）造 chosen/rejected | 低 | 提升「设定遵循」类可判别行为 |
| 角色内边界 | 「不得跳出角色」「不得说自己是 AI」+ 敏感话题在角色内转开 | 低 | 已在 `bench_v2` 的一致性类里测（`cons_no_break_claim` 等） |
| 事实填空对 | 从百科挖「中国的首都是___」式问答 | 低 | 修最弱的填空项（当前 0.07–0.20） |
| 工具调用 / JSON | — | — | 272M 仍学不好（结构化 0.03–0.06），等更大规模 |
