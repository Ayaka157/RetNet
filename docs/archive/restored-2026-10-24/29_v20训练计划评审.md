# 29. v20 训练计划评审（开训前）

> 写于 2026-10-17，**训练尚未启动**。本文是给决策用的评审材料：目的、数据构成、预期效果、成本、
> 风险与待拍板的选项。所有数字都标了出处；凡是估计值都写明是估计。

## 1. 这一轮要解决什么

### 1.1 唯一的核心问题

**模型从没学过新东西。** 到今天为止的五轮训练（ep1–ep4，约 20.1 小时、≈¥78）全部在
`data_cache/chat_pack_v13` 这一份 **552,330,489 token** 上反复训练；唯一 token 数**从头到尾是 0.552 B**。
累计消耗 2.76 B token 里 80% 是同一批数据的重复。

按 token/参数算：名义 5.5 token/参数，但**唯一** token/参数只有
`552,330,489 / 504,179,896 = 1.095` —— Chinchilla 的 5%。这是"原地踏步"的量化定义。

### 1.2 这一轮明确要达成 / 明确不承诺

| | |
| --- | --- |
| **要达成** | 唯一 token 从 0.552 B → **2.354 B**（+1.802 B，×4.3）；唯一 token/参数 1.095 → **4.67** |
| **要达成** | 让模型**第一次**在成规模的连续自然文本上做 next-token prediction（此前 v13 里 plain 只占 5.9%） |
| **不承诺** | 基准的知识/推理/编码分不会从 0.000 跳起来。这一轮语料里**没有代码**，中文数学只有 `open_web_math` 的英文 152 M |
| **不承诺** | 不会接近 Chinchilla 20 token/参数。4.67 仍然只有它的 23% |

### 1.3 为什么这件事之前没做

训练管线此前 `data_dir` 与 `max_steps` 写死、启动后不可变，换语料只能重启进程。已修：
`retnet_hf/plan.py` 让计划可热加载、语料可在训练中途切换（commit `ec9a49b`，已通过端到端验证）。

### 2.2 消耗计划

| 项 | 值 |
| --- | --- |
| batch | 16 × seq 2048 = **32,768 token/步** |
| Stage 0（新语料） | **55,000 步 = 1,802,240,000 token = 该语料的 64.1%**（0.64 个 pass） |
| Stage 2（对话退火） | **6,000 步 = 196,608,000 token**，语料 `chat_pack_v13`（旧数据，第 6+ 次曝光） |
| 合计 | 61,000 步 = 1,998,848,000 token |
| 一个完整 pass 需要 | 2,811,343,623 / 32,768 = **85,795 步** |

Stage 0 用 `RandomSampler` 均匀抽 64.1% 的行，**不是顺序读前 64%**，所以 7 个来源的配比保持不变。

### 2.3 验证集（**故意不换**）

- 主验证：`chat_pack_v13` 的 val（833 行）——与前五轮**同一把尺子**，保证曲线前后可比。
  设计上 `Plan.val_dir` 与训练语料分离，就是为了防止"换语料顺手换了验证集"这种假进步。
- 域内验证：`pretrain_v2` 的 6 个 val 分片（5.47 M token，训练时被 `_FlatStage` 按文件名排除）。
  **开训前会先用 ep3 在这上面测一次基线**，否则训完没有"之前"可比。

## 4. 预期效果

分三档写，避免把"希望"写成"预期"。

### 4.1 会确定发生的

- 唯一 token 0.552 B → **2.354 B**；唯一 token/参数 1.095 → **4.67**。
- 模型第一次在 1.8 B token 的连续自然文本上计算 loss（此前 5 轮里 plain 只占 5.9%，累计约 164 M token）。
- 域内验证损失（`pretrain_v2` 的 held-out）会明显下降——因为它直接优化这个分布。

### 4.2 可能会发生的

- 通用中文表达、事实性知识、百科式长文的连贯性改善。理由：这是第一次让自然文本进 loss。
- 对话的"知识面"变宽，但**风格可能先退化**——Stage 0 是网页语料，退火阶段（6,000 步）才把对话拉回来。

### 4.3 不会发生的

- 代码能力不会出现（语料里 0 代码 token）。
- 中文数学不会明显改善（唯一的数学源是英文 `open_web_math`）。
- 基准的推理项不会动（没有中文 CoT 语料）。

### 4.4 一个必须提前说的风险：主验证曲线会先变差

主验证集是**对话分布**，而 Stage 0 训练在**网页/百科分布**上。预期：
- Stage 0 期间 chat-val 会**上升**（分布漂移），这不是故障；
- 退火 6,000 步会把它拉回来，但**最终值很可能仍高于 ep3 的 1.9459**。

所以这一轮的成败**不能只看 chat-val**。判据见 §6。

## 5. 成本与待拍板的选项

### 5.1 成本

| 项 | 值 |
| --- | --- |
| 时长 | 61,000 / 1.75 it/s = 34,857 s = **9.68 h** |
| GPU 费用 | 9.68 × ¥6.98 = **¥67.6** |
| 守卫上限 | tripwire 9.9 h / watchdog 11 h / 死手开关 10.2 h（都在 ¥75 以内） |

### 5.2 待拍板 A：英文占 37.7%，要不要降？

- 现状：英文 `fineweb_edu` + `cosmopedia` + `open_web_math` = 1,060.0 M（37.7%）。
- 代价：这个 20k BPE 对中文是 ~3.5 bytes/token、对英文只有 ~1.8，**同样的 token 预算，英文承载的语义更少**。
  按 token 算它占 37.7%，按"信息量"算它更低。
- 好处：这是模型第一次接触成规模的知识型文本，英文教育语料质量确实高；`open_web_math` 是唯一的数学源。
- **我的建议**：保留。理由是本轮目标是"补自然文本"，不是"极致中文配比"；把英文砍掉会让数学直接归零。

### 5.3 待拍板 B：`skypile` 占 17.9%，license 不是开源协议

- `skypile` 是 Skywork 社区协议（**非开源**），其余来源是 ODC-By / Apache-2.0 一类。
- 你的权重发布在 HF 且标注 MIT。**训练数据里有非开放协议语料，会让"MIT 权重"的出处不干净。**
- **我的建议：剔除 `skypile`**（10 个分片 504.1 M，占 17.9%）。剔除后语料 2.31 B，
  stage 0 改成 45,000 步（1.47 B token，64%）+ 退火 6,000 步 = 51,000 步 ≈ 8.1 h ≈ ¥56.5。
  唯一 token 仍从 0.552 B → 2.02 B（×3.7）。

## 6. 成功判据（可验证）

| 判据 | 门槛 | 怎么测 |
| --- | --- | --- |
| 唯一 token 增量 | ≥ 1.4 B（剔除 skypile 时）/ ≥ 1.8 B（保留时） | 训练日志的 global_step × 32,768 |
| 域内学习真的发生 | held-out `pretrain_v2` val loss 相对 ep3 基线**下降 ≥ 10%** | 开训前测基线，每个 checkpoint 后复核 |
| 对话不塌 | 退火后 chat-val 不高于 ep3 的 1.9459 + 0.15 | trainer_state 里的 eval_loss |
| 生成质量 | 抽样 20 条对话，无 ≥30% 的退化（重复/乱码/失焦） | 训练后跑 play_v2 对比 |

**如果域内 val 不降**，说明数据或管线有问题，这一轮就算失败——到时会如实报告，不掩盖。
