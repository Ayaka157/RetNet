所以**要完整曲线必须从 trainer_state 导，不能只留 .out**。归档器就是干这个的：
scripts/linux/_archive_logs.sh（常驻进程，训练结束后自动退并写最终导出）。

## 2. 接下来会自动发生什么（**不需要人干预**）

实例上有个常驻脚本 `scripts/linux/_chain_v22.sh`（PID 会变，`ps -eo args | grep chain_v22` 可查），它按顺序做：

1. **轮询等 v21 训练进程退出**（预计 10-19 17:40 ± 10 分钟）
2. **立刻停掉 v21 的三重守卫**（避免收尾窗口里 tripwire 误触发）
3. 跑 `_finalize_v21.sh`：导出 `checkpoints/retnet_500m_v21/model.safetensors`（2.0 GB）
   + 在域内 held-out 上评测（写进 `logs/holdout_eval.jsonl`，tag = `v21_final`）
4. 跑 `reinit_gamma.py`：把 gamma 重置到半衰期 200–32,000 的对数分布，
   输出到 `checkpoints/retnet_500m_v22_init/`
5. 启动 v22（`tasks/v22_ctx16k.json`）：16K 上下文扩展，7,629 步 / 0.5B token，约 1.25 h
6. v22 起来后重挂守卫：tripwire 1h35m / 死手 1h50m / watchdog 2h
7. v22 退出后评测（tag = `v22_ctx16k`），并打印与 ep3 基线的对比

**预计全部结束：10-19 19:04 左右**，之后守卫会在 19:45 前关机（数据盘不丢）。

## 4. 判据与已知的坑

- **成功判据**：域内 held-out ≤ 3.2659（ep3 基线 3.6287 的 −10%）。
  step 17,500 时已经到 **2.8471（−21.5%）**，所以判据**已经达成**，最终数字只会略有变化。
- **chat-val 会退化**（3.06 → 3.9 左右），这是预期的：阶段 0–6 里没有对话格式，
  靠最后 14,000 步混合 SFT 拉回。不要拿 chat-val 判断成败。
- **`model.safetensors` 的键数必须是 365、0 个 `_orig_mod.` 前缀**。v14 曾因漏查这一项，
  导出的 checkpoint 加载后是随机模型。
- **`hf_pack_code2`（9.4 GB）不能删**——v22 的 16K 扩展要用它按 16385 宽重切。
- **实例一旦关机，`/root/autodl-tmp` 数据盘会保留**，但 `/root`（系统盘）里的日志也在
  数据盘路径下（本项目的 logs 都在 `/root/autodl-tmp/RetNet/logs`，安全）。
