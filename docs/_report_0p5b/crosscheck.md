## 2. ② 机械化数字 token diff

抽取规则 `\d[\d,]*(?:\.\d+)?`，去掉千分位后比较。
zh 共 2,441 个 token / 709 个不同值；en 共 2,175 个 token / 654 个不同值。

| 类别 | 数量 | 裁定 |
| --- | --- | --- |
| 只在 zh 出现 | 88 | **全部裁定为「合理差异」**，见下 |
| 只在 en 出现 | 33 | 其中 32 项合理差异，1 项为 **en 独有的正确例证**（见 §2.3） |
| 双侧都有但次数不同 | 92 | 全部合理（中文是详表版，出现次数天然更多；例如 `1020` zh 17 / en 7、`0` zh 64 / en 29） |

### 2.1 只在 zh 出现：**全部是 en 的舍入源**

逐项对照后可归一为三族，**没有一项是 en 的数值与他处矛盾**：

- **同一指标的两种显示精度**（81 项）：zh 4 位 ↔ en 6 位，或 zh 2 位 ↔ en 3 位。
  例：`0.0000`↔`0.000000`、`0.0111`↔`0.011111`、`0.1029`↔`0.102941`、`0.2857`↔`0.285714`、`0.2667`↔`0.266667`、
  `0.1429`↔`0.142857`、`0.0651`↔`0.065147`、`0.0904`↔`0.090373`、`102.40`↔`102.396`、`16.200`↔`16.2`。
  （我按 `round(en, zh 的小数位) == zh` 逐项验证通过。）
- **中文独有的逐类指标**（7 项）：`54.3 / 36.7 / 52.2 / 24.3 / 14.3 / 72.0 / 78.0 / 75.8 / 78.3 / 75.6 / 91.3 / 78.9 / 100 / 88.0 / 96.0 / 66.7 / 73.3 / 0.0 / 82.0 / 93.3 / 99.2 / 96.3`
  这一类**不是精度问题，而是英文表 21 把这两列印成了「—」**（见 §5.1）。
- **提取伪差**（少量）：`3.500`/`0.038`/`0.11`/`0.8`/`1.5`/`5.9`/`1.576`/`10.0`/`14.3` 等，来自
  zh 的区间与百分比排版（如 `0.143–0.429` 在 zh 里被拆成 `0.143` 与 `0.429`，而 en 里同一区间写成 `0.142857–0.428571`）。

### 2.2 只在 en 出现

同样全部可解释：`0.011111`/`0.022222`/`0.033333`/`0.058333`/`0.065147`/`0.066667`/`0.071429`/`0.090373`/
`0.102941`/`0.120000`/`0.142857`/`0.177778`/`0.228571`/`0.266667`/`0.285714`/`0.355556`/`0.428571`/`102.396`/`16.2`
—— 全是 zh 的 6 位/3 位精度源；`68` 与 `81923` 是**文本层伪差**（见 §5.3）。

### 2.3 唯一一条真实的单侧内容：en 独有 `72.34`

英文 §3.4 缺陷③ 的例证里多引了一个 `v15c_pro6000.out 72.34`（"v15b_real.out … 1.971, ep2/ep3 1.678 / 1.743, and v15c_pro6000.out 72.34"）。

## 4. ④ Lead 指定：附录 C 那张 `longtable` 的跨页完整性

**先说方法自由度**：PyMuPDF 的 `page.find_tables()` 在这两张**纯三线表**上返回 **0 张表**（内建检测器不认这种只有 `\toprule/\midrule/\bottomrule` 的排版），所以我没有用"自动表格识别"。
改用三条**可复核**的几何/文本方法：① 绘制路径找横线；② 逐页数表头文字；③ 逐页按第一列 x 区间数行、并按 y 排序重建行序。

### 4.1 表头与三线：**每一页都正确重复 ✅**

| | 第 1 页 | 第 2 页 | 第 3 页 |
| --- | --- | --- | --- |
| 中文 | p26：`toprule` y=356.5(0.87pt)、`midrule` y=376.9(0.55pt)、**`bottomrule` y=775.6(0.87pt)** | p27：71.3 / 91.6 / **744.5** | p28：71.3 / 91.6 / **309.6** |

**"每一行的文字都没有被截断"我无法逐行证实。** 我试过用每行结论的尾部字符串做匹配，
但 LaTeX→PDF 的归一化无法做到无损：`\code{}`/`allowbreak{}`/`\gamma`/`$\times$`/`$\to$` 与 PDF 里的 `×`/`→`/`γ`、
中文引号 `“”` vs 源码 `"`、以及英文的**断词连字符**（PDF 里 `domi-` + `nated`）都会让字符串比对失败——

**"逐行文字零截断"我没有独立证实**，若要这一条，需要 latex-builder 用 `pdfbounds.py` 级别的逐行 bbox 比对或人工对照源文件抽查，别采信我这一层之外的推断。

### 5.2 ⚠️ 英文版代码片段里的连字符是 U+2010，复制粘贴后与原文件名不符

英文 PDF 的代码字体把 `:` 后的连字符渲染为 `‐`（U+2010，非 ASCII hyphen）。
例：从英文 PDF 复制得到 `modeling_retnet.py:98‐103`、`FAST‐CHUNKWISE`、`92.5%;`（分号还是 U+037E）。
中文版是正常 ASCII。⇒ 英文 PDF 的"行号/路径"**不可直接复制去 grep**。纯排版问题，不影响人眼阅读。

### 5.3 文本层伪差（不影响人眼所见）

- 中文用 Unicode 上标 `8192³` / `8192²`，英文用 `\textsuperscript`，抽取后变成 `81923` / `81922`。
