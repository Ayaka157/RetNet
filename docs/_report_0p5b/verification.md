## 3. 方法论审查：`bench_v3` 提示构造 vs 该检查点的训练格式

**结论（不是「可能」）：提示构造与训练格式在 token 化与标记层面是同一个实现，不存在口径不匹配。
冒烟跑的低分与 57.7% think 泄漏**不是**格式错配造成的，而是**生成预算与模型学到的回复长度严重不匹配**
造成的；格式错配假说被证据否定。**

### 3.1 证据：评测与训练共用同一套编码函数

### 9.3 L18/L19 为什么是 51.5% 而不是 70.2%（已定位到脚本）

零占比是**混合比例**：内部矩阵 47.107%（384 宽死区）+ 两个写回矩阵 60.331%（640 宽死区）+ 范数。
根因：**这个模型是两段生长的产物，而且是"混合配方"**。

- `checkpoints/retnet_143m_hf/config.json`：**d_model=768 / L=18 / H=12 / ffn=1536**（普通 LayerNorm）
- `scripts/grow_272m.py:25` `OLD_L, NEW_L = 18, 20` → **插入 2 个新层**，得 272M（d1024/L20/H16，`growth_old_dim=768`）
- `scripts/grow_500m.py` → 504M（d1408/L20/H22，`growth_old_dim=768`）

- **L0–L17** = 143M 的 18 层：`grow_272m` 放进 `[0:768,0:768]`（死区 `[768,1024)`），
  `grow_500m` 再放进 `[0:1024,0:1024]`（死区 `[1024,1408)`）→ **累计死区 `[768,1408)`（640）**，从未解锁。
- **L18/L19** = `grow_272m` **新插入**的层，权重按 d=1024 **全宽**随机初始化 → 272M 阶段死区仅 `[768,1024)`。
  但 `grow_272m.py:3` 的「**零残差新层**」把这两层写回残差的部分（`out_proj`/`ffn.2`）在 `[768,1024)` 上也清零，
  以保持插入的函数保真 → 写回死区扩到 `[768,1408)`（640）。
  ⇒ 内部读数 384 死 / 写回 640 死 → **51.503%** ✅ 与闭式复算逐位相符。

**副产品**：`checkpoints/retnet_500m/config.json` 的 `growth_old_dim=768` **只对 L0–L17 正确**；
L18/L19 的真实旧宽度是 **1024（读）/ 768（写回）**。`config` 是全局单值，无法表达逐层差异 ——
这是又一处「单值配置无法表达逐层事实」的静默源。

### 9.4 `gamma_new=0` 是不是设计意图？为什么没解锁？—— **是设计意图，且是自锁**

**（i）意图明确（有代码）**

- `retnet_hf/modeling_retnet.py:278-282` docstring：「the new channels are scaled independently with
  `gamma_new`/`beta_new` and **stay a zero side branch while `gamma_new=0, beta_new=0`**. This is what makes
  pre-LN width expansion strictly function-preserving」。
- 生长脚本**显式写 0**：`grow_272m.py:95-96`、`:118-119`、`:125-126`；`grow_500m.py:153`（`gn = torch.zeros(n_new)`）、`:162-163`。
- ⚠️ **模块构造时传的其实不是 0**：`RetNetBlock._norm`（`:303-304`）与 `final_norm`（`:392-394`）都传 `gamma_new=1.0, beta_new=0.0`。
  检查点里的 0 完全来自**生长脚本**。**（说明"0"是脚本作者的选择，不是结构必然。）**

**（ii）机制：`gamma_new=0` 把新通道梯度整条切断，形成闭环自锁**

`modeling_retnet.py:294-297`：

```python
def forward(self, x):
    old = self.ln_old(x[..., :768])
    new = x[..., 768:] * self.gamma_new + self.beta_new     # ← 第 296 行，自锁点
    return torch.cat([old, new], dim=-1)
```

- **正向**：`∂new/∂x_new = gamma_new = 0`。
- **反向一**：上游新通道参数的全部梯度都要过 `∂new/∂x_new` ⇒ **恒为 0** ⇒ 新增维权重永远停在初始值。
- **反向二**：`∂new/∂gamma_new = x_new`，而 `x_new ≡ 0`（残差流 `[768,1408)` 从 embedding 起就是 0，
  且 L0–L17 的写回矩阵在 `[768,1408)` 全零，谁也写不进去）⇒ **`gamma_new` 梯度恒为 0**。
- ⇒ 闭环：**`gamma_new` 不动 → 新通道梯度为 0 → 新通道保持 0 → `x_new` 保持 0 → `gamma_new` 仍不动**。
  **这是"初始化写法导致梯度恒零"的自锁**（Lead 的第二种假设），不是训练失败、不是学习率问题。

**（iii）关键反事实（最值得写进报告的一条）**

把 `gamma_new` 初始化成 **1.0**（正是 `_norm` 构造时的实参）**同样函数保真**：
`new = x_new × 1 + 0 = 0`（因为 `x_new ≡ 0`），但 `∂new/∂x_new = 1` ⇒ 梯度能流 ⇒ 新通道会解锁。
⇒ **是「置 0」这个选择杀死了这 640 维，而不是"宽度生长做不到"。** 报告不得写成"生长机制本身无效"。

### 9.5 反例：写手的「82 张量全零」是错的，实际 78

| 张量 | 元素 | 零 | 非零索引（局部） | 映射到模型维度 | 值域 |
| --- | --- | --- | --- | --- | --- |
