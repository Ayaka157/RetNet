## 3. 25 题能力验证（4 checkpoint × 6 模式，2026-08-23）

完整输入输出与逐题评分：`logs/capability_eval/capability_report.md`

| 模式 | v4(训练中) | v3 | rp_v1 | rp_v2 |
| --- | --- | --- | --- | --- |
| 续写（4 题） | 1.9 | 2.0 | 2.9 | **3.4** |
| 填空（5 题） | 0.7 | 0.6 | **1.5** | 0.7 |
| 问答（5 题） | 0.8 | 1.0 | **2.0** | 1.4 |
| 角色扮演（4 题） | 1.0 | 1.3 | 2.8 | **4.0** |
| 结构化（4 题） | 1.0 | 1.3 | **1.9** | 1.6 |
| 多轮记忆（1 题） | 1.5 | 1.0 | 3.5 | **4.0** |
| **总平均** | **1.0** | **1.1** | **2.0** | **2.0** |

### 核心发现
1. **rp_v2 交互最优**：角色扮演 4.0、多轮记忆 4.0、续写 3.4；rp_v1 在常识问答/闲聊/结构化略胜（数据配比不同，两者互补）。
2. **三个硬天花板**（所有版本一致）：常识填空（全 0.5-1.5，无版本答对「中国的首都是___」）、
   数学/推理（全 0.5，17+25 无人答对）、JSON 严格结构化（1.0-1.5）。
3. **多轮记忆是意外发现**：rp_v2 能在第二轮引用用户名字（「我叫小明」→「小明，你是在问小明吗？」）。
4. **预训练版只赢续写**：知识在长、交互被冲，符合「先变笨再变强」预期。

## 4. CoT 实测（2026-08-23）

- 直接提问「17 加 25」→ 全错；
- 加提示「请一步一步推理」→ 更乱的伪推理（「加25=10，所以加25=20」）——**100M 推理期 CoT 无效**。
- 结论：CoT 有效下限约 0.5-1B（蒸馏后），可靠推理 7B 起；本硬件 8GB 不适合（详见 04 文档）。

## 5. 如何复现评测

```powershell
# 固定题库（闲聊10+指令10+英文3+多轮3+角色扮演4）
python scripts\eval_chat.py --checkpoint <ckpt>/model.pt --tokenizer <data>/bpe_tokenizer.json --tag <名称>
# 能力验证（6 模式 25 题，CPU 推理，不占训练）
python scripts\capability_eval.py --checkpoint ... --tokenizer ... --tag ... --out logs\capability_eval\<名称>.md
```
