# 20261024_Submit_pre-audit

This directory is the **post-fix copy** of the 2026-10-20 training submission snapshot, released under the 2026-10-24 directory name.
The content is an auditable snapshot: **the rewritten training code + six documents + a standalone verification script + a manifest**.
It is not a training entry point and is not referenced by any training script; the authoritative source is still the repository `E:\Workspaces\RetNet`.

The audit report is at `_audit_fixed/AUDIT_REPORT.md` (the external audit as written, unmodified). The
code and documents in this directory are **the current state after fixing that report item by item**; the root cause, the change and the verification
for each fix are written in `FIX_LOG.md` in the same directory, and the status table is generated from a single source, `code/scripts/fix_status.py`.

  These are **explicit skips**, not fake passes.
- `pytest` explicitly excludes 5 files via `code/tests/conftest.py` (`test_checkers`,
  `test_model`, `test_bench_equivalence`, `test_play_v2_prompt`, `test_runner_lockstep`):

  which looks like "the tests are broken". The reason for each exclusion is written in the conftest.
- The 2 script-style tests are kept outside pytest, for the same reason, also written in the conftest.

## Operational notes (behavior of the current code)

| Scenario | Behavior |
|---|---|
| Starting from a pruned/grown checkpoint | when the live-parameter ratio is <95% you need `--allow_dead_params`; or first run one training pass with that switch to write a `live_params.json` baseline |
| Turning off the no-decay rule for 1-D parameters | write `no_decay_1d: false` in the config and the launcher passes `--decay_1d` (previously silently ignored) |
| Gradient coverage check | counts zero-gradient parameters after step 1; stops when the element ratio exceeds `--dead_grad_tol` (default 2%) |
| Evaluation size | `--eval_batches N` caps the number of evaluation batches; default 0 = no limit (this used to be a dead field) |
| Flat stream without eos | write `require_eos: false` for that stage in the plan (this key now really takes effect) |
| Validation-set isolation | three-layer check: path / meta.json provenance / line content; the content layer scans at most 200,000 lines by default |
| Best-model selection | no selection during training (`load_best_model_at_end=False`); compare offline with `eval_holdout.py` after training |

## Known limitations (what the auditor should know)

- **Conclusions about checkpoints and data cannot be reproduced in this snapshot**: `retnet_500m_v21_export`,
  `hf_pack_*`, `pretrain_v2` and `val_pack` are all absent from the snapshot. So **data facts** such as
  "67% zero parameters", "median live-head gamma 0.693" and "whether the v22 mixture contains eos"
  still have to be checked on the data machine; this snapshot only guarantees that the **code behavior**
  matches the implementation defects in the report.
- **The validation-set content layer is a sampling cap**: 200,000 lines by default (about 0.8 GB), and the log
  says so when truncation happens. The declared-provenance layer (meta.json) has no sampling cap, but it
  depends on the production line writing it.
- **GPU numbers are not reproduced**: throughput, peak memory and compile gains are all historical measurements;
  the verification in this snapshot was done on CPU/small models (numeric and structural assertions, not performance assertions).
- **`FIX_LOG.md` is a manual fix record**, not a generated artifact; the code and tests are authoritative.
- **Language**: all documents, document filenames, status values and verifier output are English.
  Code excerpts inside `docs/01_function_reference.md` and `docs/00F1_fix_matrix.md` are verbatim
  source, so their comments/docstrings remain in the source language (Chinese); translating the
  code itself was out of scope for this pass.

## Document generation

The code excerpts in `docs/01_function_reference.md` and `docs/00F1_fix_matrix.md` are extracted by script from the source AST/anchors, not copied by hand. The English explanations live in `code/scripts/doc_i18n/expl_en.json` and `fix_en.json`; the generator aborts if they do not cover every function/entry.

```powershell
cd code/scripts
$env:RETNET_GEN_ROOT = (Resolve-Path ..).Path
$env:RETNET_GEN_OUT  = (Resolve-Path ../../docs).Path
python _gen_code_doc.py
python _gen_fix_doc.py
```

Status is changed only in `code/scripts/fix_status.py`; check G of `verify.py` verifies that the four places agree.
