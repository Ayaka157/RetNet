# 基准 v3 · 出题契约（authoring contract）

> 面向「出题人」（人或子代理）。**只写 JSONL，不写 Python。**
> 所有判分逻辑用下面的 **checker DSL** 声明，由 `bench/checkers.py` 编译成闭包。
> 契约违反会被 `scripts/compile_bench.py` 拒绝，并且**指出行号**。

---

## 0. 为什么是 JSONL + DSL

`bench_v2.py` 把题目和判分函数焊死在 Python 里，143 项要读 646 行代码才能核对。
v3 拆开：**题目是数据，判分是声明式 DSL**。好处是出题的人（或代理）不需要会写 Python，
编译器可以静态校验每一条判据，冻结出带 SHA256 的题库，跨机器逐字节可复现。

---

## 1. 一条题目就是一个 JSON 对象，一行一个

文件必须是 **UTF-8、LF 换行、每行一个完整 JSON 对象**，不允许注释、不允许尾逗号。

```json
{"id":"rp_linghu_identity_01","cat":"角色扮演","tier":"E","family":"rp_identity","turns":[{"user":"你是谁？"}],"system":"你是令狐冲（出自笑傲江湖）。你性格豪爽不羁，不在意规矩，重情重义，说话直来直去。","max_new":80,"chk":"all:len:2..220;not_think;any:令狐冲,华山,师兄,小师妹","axes":["rp_core","identity"],"note":"baseline identity hold"}
```

### 字段表

| 字段 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `id` | ✅ | str | **全局唯一**。`^[a-z][a-z0-9_]{2,47}$`。约定 `<family>_<序号>`，序号两位数。 |
| `cat` | ✅ | str | 类别，必须是下面 §2 表里的 15 个之一（中文，逐字相同）。 |
| `tier` | ✅ | str | `E` / `M` / `H`，见 §3。 |
| `family` | ✅ | str | 题目族，`^[a-z][a-z0-9_]{2,31}$`。同一族内题目应当同质（用于族级聚合与去冗余）。**一个 JSONL 文件里 family 前缀必须体现所属模块**（如 `rp_` / `mt_` / `cons_` / `instr_` / `st_` / `rob_` / `bi_` / `safe_`），避免跨文件撞名。 |
| `turns` | ✅ | list | `[{"user": "..."}, ...]`，**1 条及以上**。多轮就是多条 `user`；历史里助手的回复由被测模型自己生成（不是预置的）。 |
| `system` | ❌ | str | 角色扮演/设定块，编码成 `<bos>设定：{system}\n`。省略即无设定。 |
| `max_new` | ✅ | int | 最大新 token 数，`8 ≤ max_new ≤ 512`。按期望回复长度给，别一味给大（慢）。 |
| `chk` | ✅ | str | checker DSL，见 §4。 |
| `axes` | ✅ | list[str] | 1–3 个能力轴标签，见 §5。用于**跨类别**聚合（如「风格保持率」「记忆保持率」）。 |
| `temp` | ❌ | float | 覆盖采样温度。仅两种用途：`0.0`（贪婪，给确定性子串题、精确匹配题）、或省略走全局默认 `0.7`。**不要写 0.3/1.2 这类中间值**——非零温度一律用全局默认，保证可比。 |
| `note` | ❌ | str | 出题意图，≤120 字符。会进题面审计报告，写清楚「这题在测什么」。 |

### 硬性约束

1. **一行一个对象**，不能换行。字符串里可以出现 `\n`（转义），但对象本身必须在同一行。
2. **`turns` 里的 `user` 不能为空**，且不能包含 `用户：` / `助手：` / `设定：` 这三个字面量（它们是编码分隔符，会污染 prompt）。
3. **`system` 不能包含** `用户：` / `助手：`。
4. 所有字符串 **UTF-8，不要用 `\uXXXX` 转义中文**（可读性）。JSON 里的引号用 `\"`。
5. `id` 在整个题库里唯一——**跨文件也不许重复**，编译器会全局查重。
6. 用 `write` 工具写文件（保证 UTF-8 无 BOM）。**不要用 PowerShell `>` / `Out-File`**。

## 3. 难度分层（`tier`）——这是 v3 的核心机制

`bench_v2` 的问题是 **70/143 项区分度 < 0.05**（大量贴地板/天花板）。
v3 每题必须标难度层，**统计时分层报告**，这样"这批题整体偏易"会立刻暴露。

| tier | 含义 | 目标通过率（272M 线） | 配额 |
| --- | --- | --- | --- |
| `E` | easy，热身/健全性检查 | 0.70 – 0.95 | **约 20%** |
| `M` | medium，**主力区间** | 0.25 – 0.75 | **约 50%** |
| `H` | hard，压力/天花板 | 0.02 – 0.35 | **约 30%** |

出题时的经验法则（来自 `logs/bench_v2/*.json` 的实测）：

- 272M **能做**：单约束格式、短回复、口癖保持、2–3 轮显式记忆、成语接龙、续写、简单事实。
- 272M **做不好**：严格 JSON、三层嵌套、多约束叠加、算术（全 0）、长输出不跑题、
  4 轮以上的隐式记忆、被诱导后仍不出戏。
- 因此 **`M` 层应该是"单约束 + 一点变化"**（例：口癖保持 + 拒绝用户让它改口癖），
  **`H` 层是"两个约束叠加"或"需要跨轮/跨距离引用"**。
- `E` 层不要出成 100% 必过的题——留一点余量，否则等于浪费算力。

## 4. checker DSL

`chk` 是一串**分号分隔**的谓词，语义是 **全部满足（AND）**。
每个谓词形如 `name` 或 `name:参数`。

**参数怎么切分，由谓词的元数决定**（这是 v3 的实现约束，出题时必须知道）：

| 元数 | 形式 | 逗号的含义 | 例子 |
| --- | --- | --- | --- |
| 多值谓词 | `name:A,B,C` | **OR**：任一命中即可 | `any:` `all:` `none:` `re:` `num:` `yaml:` `steps:` |
| 单值谓词 | `name:SPEC` | SPEC **内部**的分隔符，谓词自己解析 | `len:2..80` `dedup:0.65,4,40` `csv:2,2` `ascii:0.8,20` `number_only:123,8` |

单值谓词里的逗号是它自己的语法，**不能**用多值谓词的 OR 语义去理解。

### 转义：只有两个

`chk` 字符串里带正则，所以**不能**用「反斜杠转义下一个字符」这种规则——
`re:\d{2,3}` 会要么丢掉 `\d`、要么多切一刀，而且两种都是静默的。
DSL 只认两个转义序列，其余反斜杠一律原样保留：

| 写法 | 变成 | 说明 |
| --- | --- | --- |
| `\x2c` | `,` | 转义成字面逗号。之所以用这个拼写：它是**一个字符**，正则的长度预算不变，`{n,m}` 量词也不会被拆散 |
| `\x3b` | `;` | 转义成字面分号（正则里可以因此包含分号） |
| 其它 | 原样 | `\d` 还是 `\d`，`\.` 还是 `\.`，Windows 路径也安全 |

例：

```text
chk: "re:\d{2\x2c3};len:1..60"     // 正则 \d{2,3}
chk: "any:a\x2cb"                  // 找字面串 "a,b"，不是 "a 或 b"
chk: "eq:你好\x2c世界"              // 完全等于 "你好,世界"
```

被判定对象 `r` = 模型输出经 `cut()` 截断后的助手回复（已 `strip()`）；
`raw` 与 `r` 在 v3 里**相同**（v2 的 `raw` 名义上未截断，实际也截断了，v3 取消这个歧义）。

### 谓词表

| DSL | 元数 | 语义 |
| --- | --- | --- |
| `any:A,B,C` | 多 | 回复包含 `A`/`B`/`C` 中任意一个（**大小写敏感**，中文数字也要列全） |
| `all:A,B,C` | 多 | 回复同时包含三者 |
| `none:A,B,C` | 多 | 回复**不包含**其中任何一个 |
| `contains_all:A,B` | 多 | 同 `all`（保留别名，可读性更好） |
| `re:PAT` | 多 | 正则搜索命中（Python `re`，默认无 flag）。`.` 不匹配换行 |
| `not_re:PAT` | 多 | 正则搜索不命中 |
| `regex_count:PAT,N` | 单 | 正则命中次数 ≥ N |
| `len:LO..HI` | 单 | `LO ≤ len(r) ≤ HI`（按**字符**计，不是 token） |
| `startswith:A,B` | 多 | `r` 以其中之一开头 |
| `endswith:A,B` | 多 | `r` 以其中之一结尾 |
| `numbered:N` | 单 | 至少 N 个不同的行首编号（`1.` `2、` `（3）` `一、` `i.` 混排都算） |
| `dash_list:N` | 单 | 至少 N 行以 `-` / `*` / `•` 开头 |
| `bullets:N` | 单 | 至少 N 行是列表项（`-` `*` `•` `1.` `一、` 任一） |
| `json:KEYS` | 多 | 从回复里抠出 JSON **对象**，能 `json.loads`，且是 dict 并含全部 KEYS。对象优先于数组，且取**最外层**那个——`{"user":{"name":"x"}}` 取外层，不是内层 |
| `json_array:N` | 单 | 抠出的 JSON 是数组，长度恰为 N |
| `json_array_min:N` | 单 | 抠出的 JSON 是数组，长度 ≥ N |
| `json_nested:OUTER.INNER` | 单 | 抠出的 JSON 是 dict，含 `OUTER` 且其值是 dict 且含 `INNER` |
| `json_has:key=value` | 多 | 抠出的 JSON 是 dict，且 `key` 的值等于 `value`（不区分大小写） |
| `csv:ROWS,COLS` | 单 | 至少 ROWS 行、每行至少 COLS 个逗号分隔字段 |
| `md_table` | 无 | 含 markdown 表格分隔行（`\|---\|`） |
| `code_block` | 无 | 出现 ≥ 2 个 ``` |
| `yaml:KEYS` | 多 | 每个 KEY 都有 `^\s*KEY\s*:` 行 |
| `xml:TAG` | 多 | 同时含 `<TAG>` 与 `</TAG>` |
| `kv:KEYS` | 多 | 每个 KEY 都能匹配 `KEY\s*[:=]` |
| `steps:A,B,C` | 多 | 依次包含这些字面量（顺序敏感，用于「步骤一→步骤二」） |
| `repeat:SUB,N` | 单 | 子串 `SUB` 至少出现 N 次 |
| `num:V` / `num:V1,V2` | 多 | 出现**数值**等于 V 的独立数字（按值比较，`042` 也算 42） |
| `num_any:V1,V2` | 多 | 同 `num:`（别名） |
| `num_f:V` | 多 | 同 `num:`，显式浮点容忍版本 |
| `number_only:V[,MAXLEN[,delims]]` | 单 | `r.strip()` 去掉尾标点后**恰好等于** V，且 `len(r) ≤ MAXLEN`。加第三个字段 `delims` 则允许「答案是 123」这种短包裹 |
| `ascii:RATIO,MINLEN` | 单 | 非 ASCII 字符占比 ≤ `1-RATIO`，且 `len(r) ≥ MINLEN`（英文回复护栏） |
| `zh_ratio:RATIO,MINLEN` | 单 | 中文字符占比 ≥ RATIO 且 `len ≥ MINLEN`（中文回复护栏） |
| `dedup:RATIO,N,MINLEN` | 单 | `N`-gram 去重率 ≥ RATIO（**退化重复护栏**）。默认建议 `dedup:0.65,4,40` |
| `not_think` | 无 | 不是「开了 `<think>` 却没关」的泄漏态 |
| `think_leak` | 无 | **是**泄漏态（只用于专门测泄漏的题，正常题别用） |
| `not_echo_user` | 无 | 回复前 12 字不等于用户那句话的前 12 字（防复读机） |
| `not_echo_prompt` | 单 | 回复里不含题目的长片段（默认 8 字，可给 `not_echo_prompt:6` 调）。**模板型题目的必需护栏**：题目里引用了判据锚点时（如「用『要是……就……』造一个句子」），光有 `all:` 会被「把题目抄一遍」白拿分，这条才是真正在判「有没有造句」 |
| `sentences:N` | 单 | 至少 N 个句末标点。**中英都算**：`。！？!?.;；` 与换行 |
| `punct_free` | 无 | 不含任何 `。，！？、；：,.!?;:` |
| `caps:WORD` | 多 | `WORD` 的大写形式出现（ALL CAPS 约束） |
| `eq:VALUE` | 单 | `r` 与 `VALUE` 完全相等（配合 `temp:0.0` 使用） |
| `is_int_in:LO,HI` | 单 | `r` 能解析成整数且落在 `[LO,HI]` |
| `max_tokens:N` | 单 | 本项生成的新 token 数 ≤ N（防「话太多」） |
| `not_empty` | 无 | 回复非空（**弱判据**，只用于配合别的主判据，不要单独用） |

> ⚠️ **`dedup:` 的 MINLEN 是「够不够长到可以判定」的门槛，不是及格线。**
> 回复短于 MINLEN 时该谓词**弃权（返回 True）**，长度要求交给 `len:`。
> 这样两个护栏互不干扰：`dedup` 只抓「够长但复读」，`len` 只抓「太短」。
> 如果你想让「必须写满 N 字」成为硬要求，请显式写 `len:N..`。
> 建议配比：`len:12..400;dedup:0.60,4,60`（长回答）、`len:2..120;dedup:0.65,4,40`（中等）。

### 组合与否定

- **NOT**：`!name:参数`（前缀 `!`）。例：`!any:喵` = 不出现「喵」。
- 整串是 AND；需要 OR 时靠谓词内部的候选列表，**不要指望 DSL 层提供 OR 组合子**。
- 想表达「是 A 或者 B 整体成立」，就写 `any:A,B`——这正是绝大多数场景。

### 写判据的三条纪律

1. **宁可宽松，不要误杀。** 小模型会用同义词、会加语气词。判据只抓**语义上不可替代**的锚点
   （例如问首都就抓 `北京`；要求口癖就抓 `喵`）。
2. **每个开放式题目都要带退化护栏**：`dedup:0.65,4,40`（或 `sentences:2`）。
   `bench_v2` 里小模型的典型失败模式是复读同一个 4-gram 到 `max_new` 用尽——这种输出必须是 0 分。
3. **精确题用 `temp:0.0` + `num:` / `eq:`**，别在采样下判精确值。

### 反面例子（编译器会警告）

```text
chk: "any:北京"                      // ✗ 太松：回复里出现"北京"两个字的任何地方都算过
chk: "len:0..99999"                  // ✗ 空判据
chk: "all:我不确定,抱歉"             // ✗ 这是拒答，不是能力
chk: "re:^"                          // ✗ 恒真
```

## 6. 写完之后

1. `id` 自查：同文件内、以及**跨文件**不重复（用 `family` 前缀隔开）。
2. 行数自查：`(Get-Content file.jsonl).Count` 必须等于你被分配的配额。
3. 每行都能解析：
   `python -c "import json,sys;[json.loads(l) for l in open(sys.argv[1],encoding='utf-8') if l.strip()]" <file>`
4. 交付时在回复里报告：**文件名 / 总行数 / 各类别行数 / tier 分布 / 用到的 checker 谓词集合**。

编译器 `scripts/compile_bench.py` 会对每条做全量校验并输出 `bench/data/bench_v3.jsonl` +
`bench/data/bench_v3.manifest.json`。
