## E01 生长时新行必须随机、新列才置零

**状态**：已修

`scripts/grow_500m.py` L144–L165

```python
    def fill(p, old_key, out_d, in_d, gen):
        """旧权重放左上角；新**列**置 0（块内隔离），新**行**随机（让新单元有输出）。

        为什么是"列 0 行随机"，而不是全 0 或全随机：

        * 新列若随机，它会立刻改变旧维度的输出，函数不再保真，且无法用任何
          门控挡住（扰动已经进了旧维度）。所以新列必须是 0。
        * 新行若全 0，新单元（新头、新隐藏单元）的输出恒为 0，下游那些
          "读新单元"的列拿到的输入是 0，梯度 `上游 x 0 = 0`，整条新子网
          永远学不动——v21 的 338M 死参数就是这么来的。
        * 新行随机后：新单元有非零输出 -> 下游新列拿到非零输入 -> 新列在
          第 1 步就有梯度；新列变非零后，新行在第 2 步拿到梯度。
          这是一条**自愈的级联**，不是死锁。
        """
        w = torch.zeros(out_d, in_d)
        ow = old_sd[old_key]
        w[: ow.shape[0], : ow.shape[1]] = ow
        n_new_rows = out_d - ow.shape[0]
        if n_new_rows > 0:
            w[ow.shape[0]:, : ow.shape[1]] = \
                torch.randn(n_new_rows, ow.shape[1], generator=gen) * NEW_ROW_INIT_STD
        new_sd[p] = w
```

旧实现先用 torch.zeros 建整个新矩阵，再把旧权重贴到左上角，于是新增的行与列**同时**为 0。这个组合会形成梯度死锁：新列是 0，则新行输出的梯度乘到 0；新行是 0，则新列收到的上游梯度也乘到 0，两个 0 互为对方梯度的因子，从第 0 步起就精确不动。修复只改一侧：新列保持 0，因为新列若随机会立刻改变旧维度的输出、破坏函数保真，而且这种扰动没有任何门控能挡住；新行改成 N(0, NEW_ROW_INIT_STD)。新行随机让新单元先有非零输出，下游“读新单元”的列在第 1 步就拿到非零输入并开始学习；这些列变非零之后，新行自己在第 2 步拿到梯度。这是一条自愈级联，而不是死锁。函数保真仍然成立：新列是 0，所以新维度不会影响旧维度的输出。该行为由 tests/test_growth_trainable.py 的反向用例守护：把 NEW_ROW_INIT_STD 改回 0，生长脚本必须拒绝落盘。

验证方式：`tests/test_growth_trainable.py::test_growth_guard_fails_when_reverted_to_zeros` 把 `NEW_ROW_INIT_STD` 改回 0，断言生长脚本返回 2 且不落盘；正常用例要求 rc∈{0,1} 且 `model.safetensors` 存在。旧权重的实测基线是 338,120,704 个元素精确为 0，占 67.06%。

## E02 中间层门控必须为 1，final_norm 门控为 0

**状态**：已修

`scripts/grow_500m.py` L167–L191

```python
    def grow_norm(new_p, old_prefix, d_new, gate):
        """两段式 norm：旧段照搬，新段一律重设为 gate（不再继承源的零门）。

        gate 的取值不是随手写的，它决定新维度是"能学"还是"永久死"：

        * 中间层（norm1/norm2）必须 gate=1.0。新维度要进入 q/k/v 的**新列**，
          而新列初始为 0；若 gate 也是 0，则新列乘到的输入恒 0，
          ``dL/dW_newcol = 上游 x 0 = 0``，新列永远学不动（这是 v21 的死因）。
          取 1.0 后输入非零，新列即使初值为 0 也能拿到非零梯度。
        * final_norm 必须 gate=0.0。它是新维度通往 logits 的唯一出口，
          置 0 才能保证"生长后 logits 不变"；它的梯度来自
          ``dL/dgamma = 上游_logits x x_new``，上游经 tied lm_head 的新列（随机非零）
          回传，故第一步就能学到非零。

        两者合起来：函数在输出端严格保真，而新参数从第 0/1 步起就有梯度。
        """
        if src_grown:
            new_sd[new_p + ".ln_old.weight"] = old_sd[old_prefix + ".ln_old.weight"].clone()
            new_sd[new_p + ".ln_old.bias"] = old_sd[old_prefix + ".ln_old.bias"].clone()
        else:
            new_sd[new_p + ".ln_old.weight"] = old_sd[old_prefix + ".weight"].clone()
            new_sd[new_p + ".ln_old.bias"] = old_sd[old_prefix + ".bias"].clone()
        n_new = d_new - grow_old_dim
        new_sd[new_p + ".gamma_new"] = torch.full((n_new,), float(gate))
        new_sd[new_p + ".beta_new"] = torch.zeros(n_new)
```

旧实现把新段的 gamma_new 与 beta_new 全部置 0，并且把源模型已有的零段继续搬过来，注释里称之为“零旁支”。问题在于这个门是乘法门：gamma_new=0 时，新维度不仅前向恒 0，它自己的梯度也恒 0，因为它等于“下游回传梯度 × 新维度输入”，而下游那些读新维度的列初始同样是 0。修复把门控按位置分开：中间层 norm1/norm2 设为 1.0，让新维度能流进 q/k/v 的新列，新列即使初值为 0 也能因为输入非零而拿到梯度；final_norm 设为 0.0，它是新维度通往 logits 的唯一出口，置零保证生长瞬间 logits 逐值不变。final_norm 的门自己会学：它的梯度等于“上游 logits 梯度 × 新维度”，上游经 tied lm_head 的新列（随机非零）回传，所以第一步就非零。两者合起来实现“输出端严格保真、新参数从第 0/1 步起可学”，Tests/test_growth_trainable.py 的旧行为用例会验证门控归零时脚本拒绝保存。

验证方式：同一测试把 `BLOCK_GATE` 改成 0，覆盖“中间层门控归零”的旧行为；正常路径要求 final_norm 的 `gamma_new` 全 0、中间层全 1。旧模型实测 41 个 `gamma_new` 张量全部为 0，这正是“宽度生长从未生效”的直接证据。

## E03 embedding 的死列与新列必须重新随机

**状态**：已修

`scripts/grow_500m.py` L193–L202

```python
    # 嵌入：旧列照搬；[grow_old_dim:] 一律重新随机。
    # 这一段既包含本次新增的 384 列，也包含上一次生长遗留的 256 个死列——
    # 它们必须一起复活，否则"函数保真"仍然成立，但新维度没有信号源，
    # 下游新列拿到的输入仍然是 0，梯度仍然是 0。
    gen = torch.Generator().manual_seed(1234)
    emb = torch.zeros(cfg.vocab_size, NEW_D)
    emb[:, :grow_old_dim] = old_sd["embedding.weight"][:, :grow_old_dim]
    rev = emb[:, grow_old_dim:]
    emb[:, grow_old_dim:] = torch.randn(rev.shape, generator=gen) * 0.02
    new_sd["embedding.weight"] = emb
```

旧实现把 embedding 的新列留成 0。这一列同时承担两个角色：输入侧的 token 向量，以及（因为 tie_weights）输出侧的分类器权重。留 0 的直接后果是第 0 层新维度拿不到任何信号，整条新子网没有入口。修复把 [grow_old_dim:] 全部重新随机（N(0,0.02)），注意起点不是 OLD_D 而是 grow_old_dim：源模型上一次生长留下的 256 列同样是死的，只复活本次新增的 384 列没有意义，必须把 640 列一起复活。函数保真仍然成立，因为 final_norm 的 gamma_new=0 把新维度挡在 logits 之外；而这 640 列的随机值正是整条新维度唯一的非零信号源。这条与 E01、E02 是一组：没有非零输入，新列的梯度仍然为 0；没有新行随机，新单元仍然没有输出；三者缺一，67% 死参数就会复现。

验证方式：生长后统计 embedding 的列，前 `grow_old_dim` 列必须非零，其后 640 列不得全零。旧模型实测 embedding 形状 [20000,1408]，后 640 列 absmax 精确为 0，活跃列只有 0–767，与“新维度没有信号源”完全吻合。

## E04 生长脚本必须校验可训性，而不只是函数保真

**状态**：已修

`scripts/grow_500m.py` L272–L295

```python
    print(f"[trainable] 跑 5 步反向，seq={args.seq}，统计零梯度参数 ...", flush=True)
    new.train()
    opt = torch.optim.AdamW(new.parameters(), lr=1e-4)
    probe = torch.randint(1, cfg.vocab_size, (2, args.seq))
    for _ in range(5):
        opt.zero_grad(set_to_none=True)
        out = new(probe, labels=probe)
        out.loss.backward()
        opt.step()
    dead = [n for n, p in new.named_parameters()
            if p.grad is None or p.grad.abs().max().item() == 0.0]
    trainable = not dead
    if dead:
        print(f"[trainable] ❌ {len(dead)} 个参数梯度恒 0：")
        for name in dead[:12]:
            print("    ", name)
    else:
        print("[trainable] ✅ 全部参数梯度非零")

    # **两道校验都过才落盘**：只保真但不可训的检查点，
    # 静默产出的就是 v21 那种"67% 参数是 0"的模型。
    if verified is False or not trainable:
        print("❌ 校验未通过 —— 拒绝保存。先修映射/初始化，别拿这个检查点训练。")
        return 2
```

旧脚本的校验只有一条：max|Δlogits| 是否小于容差。这条检查在设计上就不可能失败，因为一个恒零旁支恰恰是最完美的函数保真——它什么都不影响，所以它必然通过。修复增加第二道校验：加载生长后的模型，跑 5 步真实反向（AdamW，lr=1e-4），然后逐参数检查 grad.abs().max() 是否大于 0。用 5 步而不是 1 步，是因为新维度是级联自愈的：第 0 步只有 embedding 新列与读新输入的列有梯度；第 1 步新列变非零，读它们的下游列开始有梯度；第 2 步新单元的输出投影拿到梯度。5 步足够走完这条链，仍为零的参数就是真死。两道校验都通过才落盘；任何一道失败返回 2 并拒绝保存。tests/test_growth_trainable.py 用 monkeypatch 把新行随机改成 0，断言脚本必须返回 2 且不落盘，从而证明这道守卫确实会失败，而不是一个永远为真的装饰。

验证方式：`test_growth_trainable.py` 的两个用例一正一反，正向要求校验通过并落盘，反向要求校验失败并拒绝落盘。旧脚本只有 `max|Δlogits|` 一条，任何恒零旁支都能通过，所以这条反例本身就是“旧校验不可能失败”的证明。

## E05 GrowthLayerNorm 的新维度门控默认必须是 1

**状态**：已修（默认值 + 测试）

`retnet_hf/modeling_retnet.py` L298–L303

```python
    def __init__(self, old_dim: int, new_dim: int, eps: float = 1e-5,
                 gamma_new: float = 1.0, beta_new: float = 0.0):
        super().__init__()
        self.ln_old = nn.LayerNorm(old_dim, eps=eps)
        self.gamma_new = nn.Parameter(torch.full((new_dim - old_dim,), gamma_new))
        self.beta_new = nn.Parameter(torch.full((new_dim - old_dim,), beta_new))
```

这个类的构造函数默认 gamma_new=1.0、beta_new=0，本身是正确的；问题出在生长脚本显式把它覆盖成 0，并且旧代码没有任何地方守住这个默认值。E05 的修复是把它变成可测的契约：构造出的 GrowthLayerNorm 必须满足 gamma_new 全 1、beta_new 全 0；tests/test_regressions_extra.py 直接断言这一点。为什么默认值必须是 1 而不是 0：新维度不做归一化，gamma_new 是它唯一的缩放门；门为 0 时前向恒 0，而它自己的梯度等于“下游回传 × 新维度输入”，下游读新维度的权重同样是 0，于是永久死锁。默认 1 让新维度在构造时就可达，零旁支的效果改由 final_norm 的输出门控实现——那里置 0 只挡输出、不挡梯度，因为上游 logits 的梯度经 tied embedding 的新列仍能回传。

验证方式：`tests/test_regressions_extra.py::test_growth_ln_new_gate_defaults_to_one` 直接断言构造出的 `GrowthLayerNorm.gamma_new` 全 1、`beta_new` 全 0。旧模型里这 41 个张量全零，而类默认值本身是 1——说明破坏发生在生长脚本覆写的那一步，而不是类设计。

旧注释写着“growth 里 gamma=0 的张量仍参与前向，梯度存在只是为 0”，并据此关掉 DDP 的find_unused_parameters，结论是“本模型确实没有未使用参数”。这段推理在事实层面是对的——全零梯度确实不是 None——但它恰好掩盖了 bug：它确认了“有梯度”，却没问“梯度是不是恒等于 0”。修复不是改行为（关掉这个开关省一次 autograd 遍历是合理的），而是改叙述并补上真正的检查：注释明确写出这个开关检测的是 None 而不是数值，真正的守卫由 _preflight 的活参数比例与生长脚本的 5 步梯度覆盖承担。一个注释能决定后来者是否去查零梯度，所以它和代码一样需要被审计——这条错误的代价是 338M 参数静默跑完 16 万步。

```python
    """返回 (非零参数数, 总参数数, 比例)。参数量本身不说明任何问题（E08）。"""
```

```python
    def _check_boundaries(self, sample: int = 2_000_000) -> None:
        """抽查前 sample 个 token 里是否出现 eos；没有就拒绝。

        eos id=2 由 tokenizer 固定（pad=0 / bos=1 / eos=2），见

        if not self.shards:
            return
        per = max(1, sample // len(self.shards))
        seen = 0
        for _p, arr, _n in self.shards:
```

```python
    def gc_stage(self, i: int) -> int:
        """删除第 i 段的**数据文件**（已消费完才调）。返回释放字节数。

        安全约束（宁可少删也不能删错）：

        3. 该目录若是验证集目录，跳过。
        """
        if not (0 <= i < len(self._specs)):
            return 0
        sp = self._specs[i]
        d = Path(sp["data_dir"]).resolve()
        for j, other in enumerate(self._specs):
            if j != i and Path(other["data_dir"]).resolve() == d:
                print(f"[gc] 跳过阶段 {i}「{sp['name']}」：目录与阶段 {j} 相同", flush=True)
                return 0

        except Exception as exc:                                # noqa: BLE001
            print(f"[gc] 拒绝删除阶段 {i}「{sp['name']}」：{meta} 读不了（{exc}）",
                  flush=True)
            return 0
        if not (m.get("rebuild_cmd") or m.get("source_ids")):
            print(f"[gc] 拒绝删除阶段 {i}「{sp['name']}」：{meta} 里没有 "
```

```python
    def _scan(self):
        """扫描目录，返回 (shards, starts, rows)。

        **跳过打不开的分片**：数据可能正在从外面传进来，文件被截断时
        ``np.load(mmap_mode=...)`` 会抛 ``ValueError: mmap length is greater than
        file size``。这里选择跳过而不是崩——下一轮 ``refresh()`` 会把它收进来。
        """
        width = self.seq_len + 1
        files = sorted(p for p in self.data_dir.glob("*.npy") if "val" not in p.name.lower())
        if self.exclude:
            files = [p for p in files if not p.name.startswith(self.exclude)]
        shards, starts, total = [], [], 0
        signature = []
        for p in files:
            try:
                arr = np.load(p, mmap_mode="r")
            except Exception:                                   # noqa: BLE001
                continue          # 正在写入 / 损坏，等下次 refresh
            if arr.ndim != 1:
                continue
            st = p.stat()
            n = arr.shape[0] // width
            if n == 0:
                continue
            shards.append((p, arr, n))
            starts.append(total)
            total += n
            signature.append((p.name, st.st_mtime_ns, st.st_size))
        return shards, starts, total, tuple(signature)
```

旧 refresh 只比较分片数量与总行数。一个同尺寸的分片被替换时两个值都不变，函数返回 False，训练继续用旧 mmap 读到过期内容。第一版修复把签名写成“比较时对旧列表重新 stat”，结果新旧两边读的都是文件当前状态，永远相等——测试当场抓到了这个错误，也说明“看起来对”的修复必须被能失败的测试验证。正确做法是 _scan 返回 (shards, starts, total, signature)，签名在扫描那一刻取（文件名, mtime_ns, 大小）并保存到 self._signature；refresh 只比较保存值与新扫描值。close() 时把签名一并清空，避免拿一份已不存在的签名做比较。tests/test_regressions_extra.py 先把 mmap 关闭、原地写同尺寸新内容、显式把 mtime 推到未来，再断言 refresh 返回 True 且第二次调用返回 False。

```python
    def _recurrent_retention(self, q, k, v, state):
        bsz, _, tgt_len, key_dim = q.shape
        value_head_dim = v.shape[-1]
        if state is None:
            state = torch.zeros(bsz, self.num_heads, key_dim, value_head_dim,
                                device=q.device, dtype=q.dtype)
        gamma = self.gamma.to(device=q.device, dtype=q.dtype)
        # docs/00 E21：解码时 tgt_len 恒为 1，走快路径，省掉 Python 循环与
        # list/stack 的物化。数学与下面的循环逐位相同。
        if tgt_len == 1:
            state = gamma.view(1, -1, 1, 1) * state + \
                k[:, :, 0, :].unsqueeze(-1) * v[:, :, 0, :].unsqueeze(-2)
            out = torch.sum(q[:, :, 0, :].unsqueeze(-1) * state, dim=-2).unsqueeze(2)
            return out, state
        outputs = []
        for t in range(tgt_len):
            state = gamma.view(1, -1, 1, 1) * state + \
                k[:, :, t, :].unsqueeze(-1) * v[:, :, t, :].unsqueeze(-2)
            out_t = torch.sum(q[:, :, t, :].unsqueeze(-1) * state, dim=-2)
            outputs.append(out_t)
        output = torch.stack(outputs, dim=2)
        return output, state
```

recurrent 实现是逐 token 的 Python 循环：状态按 gamma 衰减、加上当前 token 的 k⊗v、再与 q 求内积。训练不用它，但解码每个 token 都会走一次；长序列 prefill 若误用 recurrent，循环次数就是序列长度。修复增加 tgt_len==1 的快路径：解码时每次只有一步，直接做一次状态更新与一次内积，省掉 range 循环、list 追加与 torch.stack 的物化。数学与循环版逐位相同，因此不需要新的容差。tests/test_regressions_extra.py 用随机状态手写一步递推，与快路径的输出、新状态逐值比较，确保“优化”没有改语义；如果哪天有人把快路径写错（例如漏乘 gamma 或错位 q/k/v），这个测试会红。

```python
def _chunked_weighted_ce(logits, labels, wcodes=None, prompt_loss_weight=0.1,
                         chunk_tokens: int = 262_144):
    """分块计算加权交叉熵，避免把整个 [B,L,V] 转成 fp32（docs/00 E22）。

    旧实现是 ``logits_f = logits.float()`` 之后一次性 reshape 求 CE。
    对本项目（B=16, L=2048, V=20000）那一步会物化 16×2048×20000×4 ≈ 2.6 GB
    的 fp32 副本，是显存峰值的主要来源；而 logits 本身还是 bf16，已经占 1.3 GB。

    这里按 token 分块：每块只把 [chunk, V] 转 fp32，峰值降到
    chunk×V×4（默认 262144×20000×4 ≈ 21 GB？——不，chunk 是 token 数，
    实际按 N=32768 切，262144 是上限，运行时只切到 N）。
    权重码语义与旧实现完全一致：pad=0 不计、reply/plain=1、prompt=prompt_loss_weight，
    最后除以权重和；没有 wcodes 时退化为普通均值。
    """
    V = logits.shape[-1]
    flat_logits = logits.reshape(-1, V)
    flat_labels = labels.reshape(-1)
    n = flat_logits.shape[0]

    w = None
    if wcodes is not None:
        w = torch.zeros_like(wcodes, dtype=torch.float32)
        w = torch.where(wcodes == 1, torch.ones_like(w), w)
        w = torch.where(wcodes == 2, torch.full_like(w, float(prompt_loss_weight)), w)
        w = torch.where(wcodes == 3, torch.ones_like(w), w)
        w = w.reshape(-1)

    total = torch.zeros((), device=flat_logits.device, dtype=torch.float32)
    denom = torch.zeros((), device=flat_logits.device, dtype=torch.float32)
    for s in range(0, n, chunk_tokens):
        e = min(s + chunk_tokens, n)
        ce = F.cross_entropy(flat_logits[s:e].float(), flat_labels[s:e], reduction="none")
        if w is None:
            total = total + ce.sum()
            denom = denom + float(e - s)
        else:
            total = total + (ce * w[s:e]).sum()
            denom = denom + w[s:e].sum()
    return total / denom.clamp_min(1.0)
```

```python
def build_gamma(num_heads: int, formula: str = "logspace",
                tau_min: float = 128.0, tau_max: float = 8192.0) -> torch.Tensor:
    """返回 [num_heads] 的 gamma，按**头索引**排列。

    formula="logspace"：半衰期在 [tau_min, tau_max] 对数均匀；
    formula="orig"：论文的 1-2^(-5-h)，h 是头索引（半衰期 2^(5+h)）。
    """
    if num_heads <= 0:
        raise ValueError("num_heads 必须为正")
    if formula == "orig":
        return 1.0 - torch.pow(2.0, -5.0 - torch.arange(num_heads, dtype=torch.float64))
    if formula != "logspace":
        raise ValueError(f"未知 formula: {formula}")
    if not (tau_min > 0 and tau_max > 0 and tau_max >= tau_min):
        raise ValueError(f"tau 范围非法: {tau_min}..{tau_max}")
    frac = torch.linspace(0.0, 1.0, steps=num_heads, dtype=torch.float64)
    tau = tau_min * (tau_max / tau_min) ** frac
    return torch.pow(0.5, 1.0 / tau)
```
