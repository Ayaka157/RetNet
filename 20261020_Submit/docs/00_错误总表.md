## 0. 一句话

不是训练把 67% 的参数练成了 0。是**生长脚本在初始化时就把新参数写成 0，并且同时把新参数两侧都写成 0**，
于是前向恒为 0、反向链路上每一环都含 0 因子，梯度从第 0 步起精确为零。训练从头到尾没有碰过它们。

## 2. 逐条

### E01 `grow_500m.py:139` 新矩阵整体置零

```python
137:    def fill(p, old_key, out_d, in_d):
138:        """把旧权重放进新矩阵的左上角，新增行列保持 0。"""
139:        w = torch.zeros(out_d, in_d)
140:        ow = old_sd[old_key]
141:        w[: ow.shape[0], : ow.shape[1]] = ow
142:        new_sd[p] = w
```

**为什么错**：`torch.zeros` 之后只贴左上角，新增的**行**和**列**全部保持 0。

**后果**：新增输出行写不出信号；新增输入列乘到的输入也是 0。
两端的梯度分别等于 `上游 × 0` 和 `上游 × 0`，互相把对方乘成 0。

**改法**：只把**参数较少的一侧**置 0，另一侧必须随机非零（Wei et al. 2016, Network Morphism）。
对于 `[out, in]` 且 `in > out` 的矩阵，零新行；反之零新列。

**验证**：构造后跑一步，断言该张量 `.grad.abs().max() > 0`。

（参 [07][08][09][10]）

### E02 `grow_500m.py:155` 新 norm 门全 0

```python
154:        n_new = d_new - grow_old_dim
155:        gn = torch.zeros(n_new); bn = torch.zeros(n_new)
156:        if src_gn.numel():
157:            k = src_gn.numel()
158:            assert k <= n_new, f"源的 gamma_new({k}) 比新的({n_new})还大"
159:            gn[:k] = src_gn
160:            bn[:k] = src_bn
161:        # 其余保持 0 → 新增维度是零旁支
```

**为什么错**：`gamma_new` 是乘在新通道上的系数。它和 E01 的新列同时为 0，
形成 `dL/dγ ∝ W_new = 0`、`dL/dW_new ∝ γ = 0` 的互锁。

**后果**：即使 E01 改成单侧随机，只要 γ 仍是 0，新通道依然恒 0。

**改法**：`gamma_new` 初始化为 **1.0**（与 `GrowthLayerNorm.__init__` 的默认值一致，
见 `modeling_retnet.py:288`），`beta_new` 为 0。零旁支应当由"输入为 0"来保证，
不能由"门控为 0"来保证——后者会把梯度一起关掉。

**验证**：断言 `(gamma_new == 0).sum() == 0`。

（参 [08][09][13]）

### E03 `grow_500m.py:166` embedding 新列全 0

```python
165:    # 嵌入：旧列照搬，新列 0
166:    emb = torch.zeros(cfg.vocab_size, NEW_D)
167:    emb[:, :OLD_D] = old_sd["embedding.weight"]
168:    new_sd["embedding.weight"] = emb
```

**为什么错**：embedding 与 `lm_head` 权重共享（`modeling_retnet.py:398-400`）。

### E04 `grow_500m.py:214-218` 校验只比输出

```python
214:        with torch.inference_mode():
215:            d = (old(x, labels=x).logits - new(x, labels=x).logits).abs().max().item()
216:        verified = d < args.tol
217:        print(f"函数保真校验: max|Δ logits| = {d:.3e}  容差 {args.tol:.0e}  "
218:              f"{'✅ OK' if verified else '❌ FAIL'}")
```

**为什么错**：`inference_mode()` 下没有梯度，校验只看"输出有没有变"。
而一个恒零旁支恰恰是**最完美的函数保真**——它什么都不影响。**这个测试在设计上不可能失败。**

**后果**：E01–E03 造出的 338,120,704 个死参数，全部通过了这道校验。

**改法**：增加"可训性校验"——构造后跑一次前向+反向，统计
`grad 非零的参数占比`；新增参数必须全部覆盖。

**验证**：把 E01 改成全零，可训性校验必须 **FAIL**；改回单侧随机，必须 **PASS**。

（参 [10][11]）

### E05 `modeling_retnet.py:296` 新通道只做仿射

```python
294:    def forward(self, x: torch.Tensor) -> torch.Tensor:
295:        old = self.ln_old(x[..., : self.ln_old.normalized_shape[0]])
296:        new = x[..., self.ln_old.normalized_shape[0]:] * self.gamma_new + self.beta_new
297:        return torch.cat([old, new], dim=-1)
```

**为什么错**：新通道没有归一化，且乘的是可学习标量 `gamma_new`。
当 `gamma_new=0` 时，这里是一个**乘法门**；门为 0，梯度也过不去。

**后果**：与 E02 叠加成死锁。

**改法**：保持结构不变，但把 `gamma_new` 初值改为 1.0，并在 `forward` 里
加一条防御：`torch._assert` 不允许 `gamma_new` 全 0（训练中崩掉好过静默）。

（参 [08][13]）

### E07 `train.py:357-360` 把"梯度为 0"当成正常

```python
357:    # DDP 默认会把 find_unused_parameters 打开（冒烟日志：'find_unused_parameters=True
358:    # was specified in DDP constructor, but did not find any unused parameters'）。
359:    # 本模型确实没有未使用参数（growth 里 gamma=0 的张量仍参与前向，梯度存在只是为 0），
360:    # 开着只会每步多遍历一遍 autograd 图 → 纯开销。多卡时显式关掉。
```

**为什么错**：这句话把"梯度为 0"当成了"没有未使用参数"的证据。
DDP 的 `find_unused_parameters` 检测的是"梯度是否为 None"，而**全零梯度不是 None**。
所以这段推理在事实上自洽、在结论上恰好掩盖了 bug：它确认了"有梯度"，却没问"梯度是不是恒等于 0"。

**后果**：训练正常跑完，没有任何一处报"新参数没有梯度"。

**改法**：删掉这段推理，改为在 step 1 之后统计每个参数张量的 `grad.abs().max()`，
把全零项列出来；数量超过 0 就打印告警，超过阈值直接停机。

### E16 `modeling_retnet.py:180-185` 两条路径不等价

```python
180:    def _parallel_retention(self, q, k, v):
181:        bsz, _, tgt_len, _ = q.shape
182:        mask = self._decay_mask(tgt_len, q.device, q.dtype)
183:        scores = torch.matmul(q, k.transpose(-1, -2)) * mask
184:        scores = scores / scores.detach().abs().sum(dim=-1, keepdim=True).clamp_min(1.0)
185:        return torch.matmul(scores, v)
```

**为什么错**：第 177 行把 `mask` 做了 `mask/√Σmask`，第 184 行又对 `scores` 做了
一次按行绝对值和归一化；而 `_chunkwise_retention`（213-248）与
`_recurrent_retention`（197-211）**都没有这两步**。`generate()` 的 prefill 用的是
parallel（560-562），decode 用 recurrent（615-618）。**训练、prefill、decode 是三条不同的函数。**

**后果**：实测 `mean|Δlogit| = 0.0158`、argmax 一致率 99.66%；B 判断数值影响 <0.5%，
但这是"推理分布与训练分布不一致"的隐患。

**改法**：删掉 177 与 184 的两处归一化，让三条路径只差实现、不差数学。

（参 [01][04]）

## 4. 代码里应该有、但不存在的东西

1. **梯度覆盖断言**：step 1 之后，`grad is None or grad.abs().max()==0` 的参数数量必须为 0。
2. **γ 衰减断言**：step 100/1000 时 `gamma / gamma_init == 1.000`。
3. **活参数统计**：`live = (p != 0).sum()`，与 `numel()` 的比值必须 >0.95。
4. **验证集隔离断言**：`val_dir` 与任何 `stage.data_dir` 的交集为空。
5. **数据边界断言**：每个训练包抽样 1,000 行，`<eos>` 出现率必须 >0。
6. **停机条件**：域内 held-out 连续两次恶化 >0.05 nats → 停。
7. **最佳 checkpoint 保留**：按域内 held-out 排序保留，而不是按步数轮转。

这 7 条，就是这次审计的产出物。代码改完后，逐条要有对应的测试。

## 6. 计划 Agent 新发现的四条（N01–N04）

### N01 `reinit_gamma.py` 按层不按头

旧实现取 20 个 `blocks.*.msr.gamma` 张量，把张量个数当成头数，循环 `h=0..19` 生成
`1-2^(-5-h)` 再 `torch.full_like` 灌满每层 22 个头。结果每层 22 个头完全相同，
多尺度衰减被抹成一个尺度；它打印的“旧值 0.399..0.586”还是每层均值，把真实的
0.106..0.999 抹平了。修法见 `scripts/reinit_gamma.py` 的 `build_gamma`，
写入前断言同一层内取值互不相同。

（参 [03]）

### N02 gamma 中位数不能用死头混算

0.5656 是 22 头混算的结果，其中 10 个头是死的（固定 0.213622，零梯度）。
按活头算，ep3 中位 0.848（半衰期 4.21 token），v21 是 0.693（1.89 token）。
判断“记忆被 wd 吃掉多少”只能看活头；判断“分布有多碎”才看全部 440 个。
今后引用 gamma 中位数必须同时给出两个口径。

（参 [03]）

### N03 层 18/19 是 d1024，不是 d1408

逐张量统计：q_proj 输入活列 1024、输出活行 1024，v_proj 输入 1024，out_proj 输入 2048；
输入列 1024–1407 的 absmax 精确为 0。报告里看到的 `q[768:]` 非零来自 768–1023 这一段。
结论“缩核不可行”不变（仍是 18×d768 + 2×d1024 的混合宽度），但依据必须改成 1024，
否则上机核对 `live` 参数时会误判。

### N04 评测强制 parallel

`scripts/eval_holdout.py:62` 原来写死 `mode="parallel"`，理由是“与 chunkwise 数学等价”；
但 E16 证明当时 parallel 多两次归一化，两者并不等价。上一轮所有 held-out 数字
（3.6287 / 2.8471 / 3.5023）测的都不是训练的函数。修法：评测切到 chunkwise，
`chunk_size` 与训练对齐，新增 `--chunk-size`。
